# EA Tool — Requirements Spec ## 1. Purpose Build an Enterprise Architecture tool that allows an enterprise architect to catalogue, relate, and govern the full technology and business landscape of a multi-country, multi-brand organisation. The tool must mirror the Fact Sheet model used in LeanIX. ## 2. Fact Sheet types (entity models) Each Fact Sheet type is a first-class entity with its own list view, detail view, and form. ### 2.1 Business Capability Fields: name, description, level (L1/L2/L3), owner, country/entity scope, lifecycle status (active/planned/deprecated), tags, linked Applications, linked Data Objects ### 2.2 Application Fields: name, description, vendor, deployment type (SaaS/On-prem/Cloud-hosted), business criticality (mission-critical/business-critical/standard/low), lifecycle status, hosting country, owner, contract renewal date, linked Business Capabilities, linked Technologies, linked Integrations, linked Data Objects ### 2.3 Technology / Infrastructure Component Fields: name, type (database/middleware/runtime/network/cloud-service), version, vendor, end-of-life date, lifecycle status, owner, linked Applications ### 2.4 Data Object Fields: name, description, classification (public/internal/confidential/restricted), owning application, owning business capability, data residency country, regulatory flag (GDPR/SAMA/PDPL/FRA/other), lifecycle status ### 2.5 Integration Fields: name, source application, target application, integration pattern (API/ETL/event/file), protocol (REST/SOAP/Kafka/SFTP/other), data classification, owner, lifecycle status, SLA ## 3. Core features — MVP - [ ] Sidebar navigation with a section per Fact Sheet type - [ ] List view for each Fact Sheet type: sortable, filterable by status/country/owner, searchable - [ ] Detail view for each Fact Sheet: all fields + relationship panel showing linked entities with one-click navigation - [ ] Create / Edit / Archive form for each Fact Sheet type with Zod-validated inputs - [ ] Global search: search across all Fact Sheet types by name - [ ] Dashboard home: counts per Fact Sheet type, lifecycle status breakdown chart, top 5 stale records (last reviewed > 90 days) ## 4. Core features — Phase 2 - [ ] Landscape view: interactive matrix of Applications vs Business Capabilities (heat map by lifecycle status) - [ ] Integration map: directed graph visualisation of all active Integrations (use React Flow) - [ ] Data sovereignty view: table of Data Objects grouped by residency country with regulatory flag filter - [ ] Export: export any list view to CSV; export any detail view to PDF - [ ] Changelog: every create/update/archive action is logged with timestamp and user label ## 5. Data model notes - All entities share a base schema: { id, name, createdAt, updatedAt, lastReviewedAt, lifecycleStatus, ownerId, tags[], entityScope[] } - entityScope is a string array: values are country codes or brand identifiers (e.g. "SA", "AE", "EG", "PL", "UK") - Relationships are stored in a join table with: sourceId, sourceType, targetId, targetType, relationshipLabel - lifecycleStatus enum: planned | active | phaseOut | deprecated | archived ## 6. UI/UX requirements - Left sidebar: collapsible, icon + label per section, active state highlight - List views: table layout, 10 rows per page, column headers clickable to sort - Detail view: two-column layout — left 60% for fields, right 40% for relationship panel - Status badges: colour-coded (planned=blue, active=green, phaseOut=amber, deprecated=red, archived=grey) - All forms: inline validation, required field asterisks, cancel/save buttons fixed to bottom of form drawer - Responsive down to 1280px minimum width (this is a desktop tool) ## 7. Non-functional requirements - Page load under 2 seconds for list views up to 500 records - All API responses under 300ms for single-entity fetches - No external analytics or telemetry - All data stays local (no third-party cloud API calls from backend)
